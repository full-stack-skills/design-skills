# 设计执行合同

## 交付顺序

1. 固定 SH01 外壳、导航、字体、颜色、间距、输入与状态组件。
2. 完成父功能默认稳定视图及数据层级；记录哪些区域冻结。
3. 设计同一功能的其他稳定视图，保留外壳与一致的位置。
4. 为每个 A 编号操作设计必要的内联变化、抽屉、弹窗或向导；不自行更换来源页面。
5. 覆盖重要 S/E/R 状态，再走通跨页面业务流程。

## 每个设计单元必须附带

surface_id、父页面、来源、前置条件、真实字段与示例、主/次操作、成功目标、失败与取消、权限、视口、冻结区、可修改区，以及对应验收案例。无这些信息的图只算探索稿。

主视图一张设计稿只表达一个稳定页面；覆盖面需要保留父页面上下文。对比板可以辅助评审，但不能代替可独立定位的正式单元。禁止把任意几个界面拼在一张长图上宣称产品完成。

## 状态与门禁

| 维度 | 状态 | 进入下一状态的证据 |
|---|---|---|
| 功能文档 | Draft → Review → Approved | 覆盖清单、交互、异常，并获明确评审 |
| 视觉设计 | 待设计 → Draft → Review → Approved | 有单元稿、真实尺寸与人工批准 |
| 实现 | 未开始 → 进行中 → 待验收 | 实际代码、可运行入口、测试结果 |
| 验收 | 未执行 → 失败/通过 | 真实环境走通功能与交互，保留证据 |

本轮文档可以交付，但所有设计单元仍为 Draft。未经用户批准不能自动记 Approved。编译通过不能记功能完成；缺登录账号的真实站点路径记未验证。

## 评审问题

入口在哪里？当前是什么对象/账号？主操作做什么？操作中能否离开？取消回哪里？失败如何恢复？成功凭什么判断？结果下次在哪里找？回答缺失就退回该单元补合同。
