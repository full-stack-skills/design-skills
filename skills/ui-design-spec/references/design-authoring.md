# 通用设计编制规则

用于把需求与已有规格编制成可交接的普通 UI 设计。以下规则由相邻设计规格工作流抽象、重新表述，不依赖生成平台、三段提示格式、远程项目或设计系统 API；沿用本技能已有 Registry、任务源与执行职责。

## 1. 按请求裁剪交付

交付规模与 spec/execution/dispatch 模式是两个维度，不另设运行状态。

| 请求 | 应交付 | 范围约束 |
| --- | --- | --- |
| 全产品或完整功能包 | 六项设计合同、范围覆盖、任务映射和实际校验 | 已声明范围全部展开，不用示范页替代 |
| 单模块规格 | 在现有模块文件内展开同等深度的页面、状态、流程与任务引用 | 保留现有目录与命名，不重复生成整份产品需求 |
| 模糊想法 | 核心问题、具体布局/控件、必要状态、假设与待决项 | 可形成草案；不擅自增加付费、登录方式或危险权限 |
| 局部修改 | 目标页面/交互面、现有基线、变更差值、冻结范围、相关验收 | 只更新受影响合同与映射，不重设计无关页面 |
| 只读审查 | 来源、缺口、影响和建议 | 不写文件或启动执行 |

只有完整标准包使用完整包脚本和双严格开关。单文件、草案或局部交付按对应内容进行语义检查；已有结构支持项目校验时记录真实结果。不为通过完整包脚本制造空文档，也不将未运行检查写成通过。

## 2. 来源、假设与具体表达

登记来源文档、版本/章节和适用范围；已确认事实、设计建议、待确认项分列。字段、角色、权限和业务结果必须有依据；没有依据时说明假设及其影响，不填假接口、假回执或真实客户数据。演示值显式标注，规格与后续产物使用同一夹具版本。

已有规格保留稳定 ID 与批准决定，核实后只补缺口。删除页面、状态或任务映射时记录原因及受影响对象，不能通过删除状态消除报错。

把“友好、美观、现代”等描述展开为实际控件标签、内容层级、字段、尺寸依据、禁用条件、反馈与下一步。设计交接按用户任务与目标状态、空间结构、组件行为组织即可；不强制任何生成器的提示语法。技术信息仅在帮助产品使用者做决定时进入界面文案。

## 3. 共享结构与状态适用性

外壳、共享组件、视觉来源与共同交互集中定义并精确引用；各页展开业务差异、覆盖版本和例外理由。不同业务区可采用不同布局，不因复用外壳机械复制页面。

逐页审查正常、加载、空、错误、无权限、离线、部分数据；有依据的副作用再审查确认、等待、结果未知和恢复。每项记录适用性、条件、可见信息、允许动作与退出路径；不适用给业务理由。状态审查清单不是必须新增的页面或权限清单。

流程走到可观察结果：入口、前置检查、准备/编辑、必要确认、执行、核验、结果与恢复。普通读取/筛选不增加审批门；未知结果先核对实际状态，不能直接重复提交。取消交互、关闭页面与取消后台任务分别定义。

## 4. 响应式与无障碍

目标设备与视口优先取自用户、产品约束及已有基线；未确定时可提出建议并标注待确认，不将固定尺寸当事实。按目标尺寸写明区域折叠、内容优先级、固定/滚动关系、溢出和长文案行为。

逐项描述键盘操作、焦点顺序与可见焦点、抽屉/弹窗打开关闭后的焦点位置、控件标签和错误关联、非颜色状态提示、对比度与减少动效。按项目要求明确语言、文本扩展和方向适配。不适用项说明理由；只有规格时报告待验证，实际可访问性与跨端效果由产物审查或运行检查验证。

## 5. 局部变更与视觉依据

区分本地视觉定义、已批准资产和执行器实际接受的约束。文件存在或写有主题不能证明约束已被应用；生成前记录可用依据，生成后核对实际效果。

局部修改绑定同一设计单元、原任务、父资产与版本；列出目标、差值、允许变化和冻结区域。即使变更只有控件宽度，也明确影响的响应式、焦点或相邻布局；不把整个主题与无关组件塞进变更。需要扩大冻结范围时列出冲突，按已有授权和项目决策处理。

## 6. 冲突与写入恢复

来源冲突定位到受影响字段、区域、流程与任务；依赖冲突的部分保留草案/待决，独立部分继续。不得凭较新日期自行推翻已确认决定，不将草案标为可执行或批准。

本地写入失败时保留原文件，检查实际落盘内容与差异，再补写缺失部分；不要盲目覆盖或将部分写入报告为完成。来源变动后检查受影响映射与派生地图，再重建。远程写入结果未知交由执行器核对，本技能不据此重发生成或业务提交。

交付分别报告结构检查、语义审阅、实际产物和运行验证的证据、失败及未执行项。文档完成不代表视觉批准或业务完成。
