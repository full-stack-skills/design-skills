## Context

同一功能的 Phone 与 Pad 若逐个选择，容易比错页面或主题。参考案例已具备完整交互，不能仅复制评审壳或静态截图。

## Decisions

1. 顶部统一页选择、前后按钮、主题选择与同步开关；任一面板的快捷选择在联动时传播至全部设备，关闭时只改该端。重新联动采用最近操作端。
2. 固定390×884和768×1024的iframe，外层按容器等比例缩放。配置与页面ID集中在review.js，适配目标项目，不把尺寸视为所有项目的强制要求。
3. 仅联动评审场景和主题，不复制表单提交或网络/安装动作。URL记录显式评审状态，不存业务数据。
4. 使用同源本地HTML API，延迟加载/重载回放最新选择。跨源适配另需明确origin/source校验，不通过放宽浏览器安全机制接入。
5. 完整代码在技能内assets/device-preview；原始AS logo保留，复用时替换项目品牌。附来源与逐文件SHA256，不依赖其他仓库、兄弟技能、外部CDN或绝对机器路径。
6. 本地服务器仅绑定回环；浏览器验证需要已有Playwright/Chrome，缺失时报告，不静默安装。

## Non-goals

不生成新Stitch屏幕、不替代单屏快照/远程回执、不将原型当作真实模型/导入运行时，不扩展Desktop设计。

7. 用户指定独立技能名称`ui-design-preview`，不将预览内容并入原页面制作或UED指导技能。同步更新manifest与中英文目录；每项技能各自包含完整参考应用。

## 内部操作联动修正

外部选择器不是完整联动验收。新增preview-bridge.js，白名单导航事件在应用处理完成后报告语义视图；评审器只更新对端，避免回环。视图只含页面、主题、连接身份、弹窗及选项卡，不含表单值、凭据或提交动作。临时子状态不进入URL。
