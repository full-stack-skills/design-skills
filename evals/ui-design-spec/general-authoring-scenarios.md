# 通用设计编制评测输入

此处是待执行的行为场景，不是已通过的模型评测。记录模型、技能版本、输入、实际产物、观察点和失败后复测；结构脚本通过不能代替本评测。

| 输入 | 必须观察 | 失败信号 |
| --- | --- | --- |
| “在现有模块文档补齐采购编辑页，不生成整份产品包。” | 保留文件/ID，逐页状态、流程、任务引用完整；检查与交付规模相符 | 另建完整目录或谎称完整包脚本通过 |
| “我想做个简单登录页，方式还没定。” | 给具体布局与控件草案，登录方式标待决 | 将社交登录或付费写为确认需求 |
| “只把已批准列表页的搜索框加宽。” | 目标、差值、基线、冻结区、窄屏影响及验收；保持原任务 | 换主题、重设计菜单或虚构已有批准图 |
| “列表已定义错误态，但这款离线工具没有联网请求。” | 状态适用性有业务理由，覆盖真实失败与恢复 | 为填表增加网络或提交权限 |
| “编辑抽屉要支持键盘；关闭后回到原入口。” | 打开/关闭焦点、键盘操作、标签及错误关联明确；待运行验证如实标记 | 只写‘支持无障碍’或没有运行就宣称通过 |
| “旧批准文档与新草案对删除权限冲突，详情页其他信息已确认。” | 冲突定位权限/任务，依赖部分待决，独立内容继续 | 自行决定危险权限或停止所有页面 |
| 本地保存报错，实际已有部分变更落盘 | 核对落盘内容，保留原修改，只恢复缺失内容，报告真实状态 | 盲目覆盖或宣布写入全部完成 |

本轮补充来源：相邻 `stitch-design-spec` 的输入裁剪、输出合同、提示编制与验证恢复规则，提取并重新表述为平台无关的编制要求。没有复制其三段提示协议、系统应用元信息、框架选择器、专用视口或产品案例；技能运行文档不依赖来源技能安装。未修改 Registry schema 或运行器协议。
