# 六项方法论验证记录

日期：2026-10-03。范围：ui-design-spec 既有技能的关系合同、派生地图与结构校验增强。不是客服产品或视觉图稿的完成报告。

## 基线

变更前只读审查发现：动作仅检 source/target/cancel，独立失败目标、结构化菜单归属、母版/冻结边界及唯一输出未检查。

先编写失败注入，再运行旧校验器。有效扩展控制通过，16 项故障均没有 methodology 错误，形成预期失败；包括未知菜单默认页、循环菜单、遗漏页/面/动作、未知对象、独立失败目标、动作去向漂移、恢复缺失、冻结重叠、缺母版、未知任务、缺验收、重复或越界输出及坏集合。

## 修正与回归

- 新增 Registry methodology 合同；旧无扩展快照保持兼容，新完整包显式使用 --require-methodology。
- 追加菜单双向归属、状态副本、畸形类型、空路径、同级菜单重名、显式 nullable 字段、Windows ADS/尾点别名故障注入；逐轮见到失败后修正。
- 8 个测试方法，包含 28 项单项关系故障及畸形任务输入，以及合法父依赖、严格入口、来源变化、生成过期、可重复生成、只写派生文件等检查。
- 使用 bundled Python 3、-X utf8。新方法论测试通过；技能 lint 检查 16 项无错误。
- Windows 初始全套测试的旧 snapshot_provenance 因 Git core.autocrlf=true 的 CRLF 字节差异失败。核对 37 个快照：转换为 LF 后 SHA256 均与原清单一致。
- 临时 LF 副本完整 50 测试通过；随后添加快照 text/eol=lf 属性，并只在哈希与来源清单相符时恢复本地 canonical LF 字节。未更改快照正文或 provenance；恢复后的字节与 Git HEAD 相同，当前工作树完整 50 测试通过。
- 分发检查原先在 Windows 把 Git POSIX 路径和 Path 反斜杠比较，误报全部 16 技能缺失；统一为 as_posix 后分发检查通过，manifest 无新增技能。

## 独立前向演练

由隔离上下文的子智能体阅读更新技能，处理“客户中心→详情→编辑抽屉→保存超时未知结果”的场景，保持只读：

- 保留客户中心导航，详情/抽屉保持局部归属。
- 区分 navigation/local/command，未知写入结果先核对，不冒充安全重试；无幂等/查询依据时标待决。
- 未批准详情母图不影响规格规划；抽屉及继承单元的视觉依赖绑定具体父图，已批准外壳不能替代详情母图。
- 逐项列出六项输出、所需证据与尚未具备的真实字段/权限/恢复能力，不虚称完整交付，不套用外部项目主题/宽度/数量。

独立静态/内存审查发现同级名称、nullable 字段、Windows 路径别名与地图遗漏字段。随后添加回归、指纹与来源新鲜度检查。一次单模型前向演练不代表跨模型成功率或任何业务效果保证。

## 标准化复验

用户要求技能保持通用规范后，先增加标准化测试，确认旧入口、引用文档及内置案例不满足要求。随后将项目案例整体迁到仓库 evals/fixtures，保留来源字节与 provenance；技能入口、工作流、模板和合同改为独立通用规则，删除项目对照汇总。测试与 CI 改用仓库夹具路径，分发目录不依赖案例阅读。

复验：51 项测试通过，16 技能 lint 和分发检查通过，技能运行文档的本地链接无断链。新增测试约束运行文档不得重新引入项目名称或内置历史案例目录。
